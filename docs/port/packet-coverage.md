## Definitions

- **Packet table**: `clif_packetdb.hpp` plus `clif_shuffle.hpp` as the map server builds `packet_db`. It also lists
  login and char opcodes, because the client protocol is one namespace. It holds every packet rAthena *parses*
  on the map server, but only some of the packets it *sends*: most server to client packets are written from
  `PACKET_ZC_*` structs and never enter the table.
- **Known packets**: the union of the packet table and the `HEADER_*` constants of `src/map/packets.hpp` and
  `src/common/packets.hpp`.
- **Direction**: a packet with a parse function is client to server. Otherwise the `HEADER_*` name prefix decides
  (`CZ_ CA_ CH_ CT_` client to server, `ZC_ AC_ HC_ SC_ TC_` server to client), then the name rAthena's comments give.
  Packets with no name at all are *unattributed*.
- **Sendable server to client**: named server to client packets, plus unattributed table entries that rAthena's sending code
  (`clif.cpp`, `char_clif.cpp`, `loginclif.cpp`, live code at this PACKETVER, found by preprocessing with `-fdirectives-only`)
  uses: an opcode literal on a line that writes a packet type, or a `HEADER_*` name, or an enumerator registered in the table.
- **Frameable**: the client knows the length (client packet table, or a registered type), so the stream stays in sync.
  **Decodable**: a type is registered in `registeredPackets`. A packet that is neither makes `PacketDecoder` throw
  `unknownPacket` and drop the buffered bytes.
