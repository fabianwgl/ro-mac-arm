## How the client shows a skill today

Everything below is in `Packages/RagnarokGame/Sources/RagnarokGame/Engine/` (`PlaySession.swift`,
`Scene/MapScene+EventHandler.swift`, `Scene/MapScene+SkillUnit.swift`).

| Server packet | Handler | What is drawn |
|---|---|---|
| `ZC_USESKILL_ACK` (0x13e, cast start, also for ground skills) | `PlaySession.swift:371` -> `onMapObjectSkillCast` | Cast bar and the cast circle (`ef_beginspell*`, `ef_darkcasting` by element) when the cast time is above zero; then `SkillEffectTable.beginCastEffects`. Works for every skill. The target cell of a ground cast is ignored: the circle is at the caster. |
| `ZC_NOTIFY_SKILL`, `ZC_USE_SKILL` (damage, heals, buffs) | `PlaySession.swift:390,393` -> `onMapObjectSkillPerformed` | Caster action, damage numbers, heal number and sound, then the skill table: before-hit and hit effects only when damage is above zero, `effects` unless the hit is a splash, `successEffects` when the skill succeeded. |
| `ZC_NOTIFY_GROUNDSKILL` (ground skill used) | `PlaySession.swift:396` -> `onGroundSkillCast` | `SkillEffectTable.effects` on the target cell. |
| `ZC_SKILL_ENTRY5` (0x9ca, one per ground unit cell) and `ZC_SKILL_DISAPPEAR` | `PlaySession.swift:401,404` -> `onSkillUnitSpawned` / `onSkillUnitVanished` | Looping `groundEffects` of the unit's skill on its cell until the server removes the unit. Added by this change; before it the packets were decoded and dropped. |
| `ZC_NOTIFY_EFFECT`, `ZC_NOTIFY_EFFECT2` (script `specialeffect`) | `PlaySession.swift:597,601` | Level-up effects and any `EffectTable` id. |
| `ZC_MSG_STATE_CHANGE`, `ZC_MSG_STATE_CHANGE3` (buff on or off) | `PlaySession.swift:572,581` | Status icon and timer for the player only (`packet.AID == account.accountID`). No picture, and other players' buffs are ignored. `ZC_EFST_SET_ENTER` is not handled. |
| `ZC_STATE_CHANGE` (option bits: stone, poison, quicken, cloak) | `PlaySession.swift:561` -> `onMapObjectStateChanged` | Stored on the object. Only `cloak` and `invisible` are used (the sprite is hidden); stone, freeze, stun, poison, curse, the Opt3 auras and the rest are not drawn. |

Skill id to effect: `SkillEffectTable` (skill -> `beginCast`, `effects`, `beforeHit`, `hit`, `success`, `ground` lists of
effect references), effect id to pictures: `EffectTable` (hand written, 2D / 3D / cylinder / SPR / STR / WAV) and
`EffectTable+Reference` (generated, STR / SPR / WAV), unit id to skill: `SkillUnitTable`. The renderer
handles all six definition kinds, so no effect type is skipped by the engine; what is missing is data.

## Gaps, biggest first

1. **No skill specific effect: 141 of 224 active skills** (was 201).
   Every skill still gets a cast bar, damage numbers and the caster animation; only the picture on the target is
   missing. All of the reference's skill mappings and all of its STR / SPR effects are in now, so the rest needs
   effect ids and assets from outside the reference: `EffectID.swift` has 1127 ids and only 292 have a picture,
   and `FUNC` effects (below) have to be written by hand. Biggest jobs: Bard 18, Alchemist 17, Hunter 15, Sage 12, Monk 12, Wizard 11.
2. **Status pictures: 89 skills start a status, 2 are drawn** (the Cloak and Hide ones, by hiding the sprite).
   Other players' buffs are not drawn at all: `ZC_MSG_STATE_CHANGE*` is only read for the player (icon and timer), and
   `ZC_EFST_SET_ENTER` (buffs already running when a player comes into view) is not handled. The option bits (stone,
   freeze, stun, poison, curse, Quicken, Overthrust, Energy Coat, Steel Body) arrive in `ZC_STATE_CHANGE` and are stored
   but never rendered. Skills that set option bits: MG_SIGHT, MG_ENERGYCOAT, AL_RUWACH, AL_ANGELUS, KN_TWOHANDQUICKEN, KN_ONEHAND, CR_SPEARQUICKEN, WZ_SIGHTBLASTER, MO_STEELBODY, MO_BLADESTOP, MO_EXPLOSIONSPIRITS, BS_OVERTHRUST.
3. **Ground units: 42 of 45 skills still draw nothing.** Fire Wall, Pneuma and Quagmire are drawn now,
   because the reference has a per cell ground picture for exactly those. The other units have an id in `SkillUnitTable`
   and no `groundEffects`, so they stay invisible: WE_CALLBABY, MG_SAFETYWALL, AL_WARP, WZ_FIREPILLAR, WZ_ICEWALL, SA_VOLCANO, SA_DELUGE, SA_VIOLENTGALE, SA_LANDPROTECTOR, HT_SKIDTRAP, HT_LANDMINE, HT_ANKLESNARE, HT_SHOCKWAVE, HT_SANDMAN, HT_FLASHER, HT_FREEZINGTRAP, HT_BLASTMINE, HT_CLAYMORETRAP, HT_TALKIEBOX, BA_DISSONANCE, BA_WHISTLE, BA_ASSASSINCROSS, BA_POEMBRAGI, BA_APPLEIDUN, BD_LULLABY, BD_RICHMANKIM, BD_ETERNALCHAOS, BD_DRUMBATTLEFIELD, BD_RINGNIBELUNGEN, BD_ROKISWEIL, BD_INTOABYSS, BD_SIEGFRIED, DC_UGLYDANCE, DC_HUMMING, DC_DONTFORGETME, DC_FORTUNEKISS, DC_SERVICEFORYOU, PR_SANCTUARY, PR_MAGNUS, AM_DEMONSTRATION, AS_VENOMDUST, RG_GRAFFITI.

## What this change fixed

- `EffectTable+Reference.swift` (generated by `scripts/skill-effects/gen-effect-table.py`): the reference's STR, SPR
  and sound-only effects that the hand written table lacked. Each asset was checked in the kRO `data.grf` (STR file,
  every texture it names, SPR and ACT, WAV) and then loaded through the app's own `EffectAssetLoader`: all load.
  Skipped: the `FUNC` ids, `ef_item316` (file missing from the client) and `ef_ado_str` (the STR parser rejects its
  non-ASCII texture name).
- `SkillEffectTable`: 66 more skills (the reference's `SkillEffect.js` plus name-matched Slow Poison, Repair Weapon,
  Envenom, Spell Breaker, Dispell, Magic Rod, the four endow skills, Chain Combo) and a `groundEffects` slot.
- Ground units: `SkillUnitTable` (102 unit ids, each checked against rAthena's `e_skill_unit_id` and `skill_db.yml`),
  the two packet cases in `PlaySession` and `MapScene+SkillUnit.swift`.
- Tests (`swift test --package-path Packages/RagnarokEffects`): every skill effect reference resolves to a
  definition, no id is in both tables, well formed file names, the unit table.
